# Video routing and artifact chain

Read this reference when selecting the HyperFrames workflow or resuming an episode.

## Resume by artifact

| Latest approved state | Start with |
|---|---|
| Topic, article, research, or rough draft | `/to-spec-beats` |
| `BEATS.md` | `/to-narration` |
| `NARRATION.md` | `/to-scenes` |
| `SCENES.md` | `/to-storyboard` |
| `STORYBOARD.md` | `/to-video` |

Existing later artifacts do not make earlier ones optional. Save pasted source material as `SOURCE.md`; preserve supplied files in place. Backfill a missing owner artifact before production so later revisions have one authoritative home.

## Route by deliverable

Ask whether the presentation is faceless. Then apply `/hyperframes` routing contracts:

- Use `/general-video` for custom, longer, multi-scene, mixed-media, or otherwise freeform episodes.
- Use `/faceless-explainer` only after the user confirms faceless and its current duration and deliverable contract fits.
- Use another specialized workflow when the requested deliverable matches it more closely, such as a talking-head recut or product launch video.

The selected route owns HyperFrames implementation. The `to-*` chain owns planning artifacts and the production state machine.

## Revision ownership

| Finding | Revise |
|---|---|
| Wrong claim, order, scope, or audience transformation | `BEATS.md` |
| Awkward spoken language, overload, or duration budget | `NARRATION.md` |
| Weak metaphor, static presentation, repetitive worlds, or missing event | `SCENES.md` |
| Poor framing, coverage, camera progression, or transition geometry | `STORYBOARD.md` |
| Playback rhythm, voice timing, implementation, or render defect | `/to-video` production state |

Propagate every upstream change through downstream artifacts before returning to production.
